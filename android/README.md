# Passel for Android

A first version of Passel on Android: the same `pass` vault as the
desktop app, opened with the same key.

- A setup wizard, like the desktop's: your key (import the backup made
  on a computer, or create one and share its public key), then an
  existing vault to download from its HTTPS address with a personal
  access token, or a new vault to create, online in an empty repository
  or only on the phone. "Check" tells whether an address holds a vault,
  is empty, or refuses the token.
- Several vaults: switch from the title bar, add one (the same wizard),
  or remove one from the phone.
- Browse and search entries; show and copy passwords and fields (marked
  sensitive, cleared from the clipboard after 45 s); one-time password
  codes with a countdown ring.
- Create, edit and delete entries. Each change is committed and synced
  right away, or kept on the phone until the next sync when offline.
- Sync both ways: changes made elsewhere come in, edits of different
  entries merge. When the same entry changed on both sides, the phone's
  version is sent as a `passel-unmerged/<commit>` branch to merge on a
  computer; the next sync on the phone then catches up. Nothing is lost.

Not there yet: biometric unlock, autofill, SSH remotes, and settings to
change a vault's remote, token or name after setup.

## How it fits together

```
android/app (Kotlin, Compose)
   │  io.pierrotws.passel.core.*  ← generated by UniFFI
   ▼
crates/passel-ffi  (libpassel_ffi.so: the mobile API)
   ▼
crates/passel-core (rpgp feature: keyring in the app's storage;
                    StoredCredentials: the token, kept in memory)
```

- `Passel` (Rust) owns the keyring (`files/passel/keys`) and the vaults
  (`files/passel/vaults/<name>`, listed in `vaults.json`; new vaults
  are made with core's `SetupPlan`, like the desktop wizard). Every call
  blocks: the app calls it on `Dispatchers.IO`.
- Key passphrases are asked from Rust through `PassphrasePrompt`;
  `PromptBroker` shows the dialog and hands the answer back. They stay
  cached until **Lock**.
- Tokens (one per host) are stored encrypted with an Android Keystore
  key (`RemoteSecrets`) and given to Rust at each start.
- The app excludes its data from backups, and release builds block
  screenshots (`FLAG_SECURE`).

## Building

Needs the Android SDK (platform 37.1), the NDK, JDK 21 and Rust with the
Android targets:

```bash
rustup target add aarch64-linux-android x86_64-linux-android
cd android
./gradlew assembleDebug                         # arm64 phones + x86_64 emulator
./gradlew assembleDebug -Ppassel.abis=x86_64    # emulator only, faster
```

Gradle runs `build-rust.sh` first: it builds `libpassel_ffi.so` for each
ABI (always optimized: key derivation is too slow otherwise) and
generates the Kotlin bindings into `app/build/generated/rust`. The NDK is
found through `ANDROID_NDK_HOME`, or the newest one in the SDK.

The Rust side is tested on the desktop: `cargo test -p passel-ffi` runs
the whole mobile API (key, clone, edit, sync, conflict) against a local
remote.

## Publishing on Google Play

Each release (release-please's tag, `vX.Y.Z`) is built, signed with the
upload key and sent to Play's **internal testing** track by the
`google-play` job of `.github/workflows/packages.yml`. Promote a build to
closed testing or production by hand in Play Console. The version comes
from `passel.version` in `gradle.properties` (bumped by release-please);
the version code is derived from it (`1.2.3` → 1002003).

One-time setup:

1. **Play Console**: create the app (Passel, free). Fill in what *App
   content* asks for (privacy policy, data safety, ads, content rating,
   target audience) and add testers to *Testing › Internal testing*.
2. **Upload key** (keep it and its passwords safe; Google signs the
   installed app with its own key through Play App Signing):

   ```bash
   keytool -genkeypair -keystore passel-upload.jks -alias upload \
     -keyalg RSA -keysize 4096 -validity 10000
   ```

3. **First upload, by hand**: Play only accepts uploads through its API
   once an app bundle was uploaded in Play Console.

   ```bash
   cd android
   PASSEL_UPLOAD_KEYSTORE=/path/to/passel-upload.jks \
   PASSEL_UPLOAD_KEYSTORE_PASSWORD=… PASSEL_UPLOAD_KEY_ALIAS=upload PASSEL_UPLOAD_KEY_PASSWORD=… \
     ./gradlew "-Ppassel.abis=arm64-v8a armeabi-v7a x86_64" bundleRelease
   ```

   Upload `app/build/outputs/bundle/release/app-release.aab` as a new
   internal testing release (this also sets the package name,
   `io.pierrotws.passel`, and enrolls Play App Signing).
4. **Service account**: in Google Cloud, enable the *Google Play Android
   Developer API*, create a service account and a JSON key for it. In
   Play Console, *Users and permissions* › invite its email, with the
   *Release apps to testing tracks* permission on Passel.
5. **GitHub**: *Settings › Environments*, create `google-play`; under
   *Deployment branches and tags*, allow only tags matching `v*` (like
   `aur`). Add these environment secrets:

   | Secret | Value |
   | --- | --- |
   | `PLAY_SERVICE_ACCOUNT_JSON` | the service account's JSON key |
   | `PLAY_UPLOAD_KEYSTORE_BASE64` | `base64 -w0 passel-upload.jks` |
   | `PLAY_UPLOAD_KEYSTORE_PASSWORD` | the keystore's password |
   | `PLAY_UPLOAD_KEY_ALIAS` | `upload` |
   | `PLAY_UPLOAD_KEY_PASSWORD` | the key's password |

Until the secrets exist, releases still go out; the job just notes that
Google Play was skipped.

# Gnome-Vault — Code Review (round 3)

A pass-compatible password manager: GTK4/Adwaita + Rust, ~11k LOC, GPGME for crypto, git2 for sync. Two prior review rounds have closed the structural issues; this pass is grouped by severity and focuses on what's actually wrong NOW.

## Important

## Minor

- **`rebuild_vault_tree` calls `update_selection_layout(false)` on every search keystroke.** `src/ui/window/mod.rs:784-798`. Layout doesn't change between keystrokes; only the selection model does.
- **`EntryView::resize_title_entry` runs per keystroke and also updates the hidden `title_label`.** `src/ui/entry_view/mod.rs:433-444, 123-133`. The label is only visible when the entry is hidden. Move the label update into `set_editable_mode(false)` so it refreshes when leaving edit mode, not on every keystroke.
- **Magic numbers `Duration::from_millis(100)`, `Duration::from_millis(50)`, `for _ in 0..32`, `for _ in 0..16` in autoload + group_content.** `src/ui/window/autoload.rs:43, 54`, `src/ui/window/group_content.rs:151, 156`. Pull these next to the existing `CHANGES_PAGE_SIZE` etc. consts so the polling cadence is one grep away.
- **`is_otp_url` uses `get(..10)` rather than `is_char_boundary`-aware slicing.** `src/helpers/otp.rs:33-38`. `get(..10).is_some_and(|p| p.eq_ignore_ascii_case("otpauth://"))` works but is awkward. Cosmetic.
- **`EntryView::set_field_row_editable`, `read_field_row`, and `field_row_drag_handle` keep four field-row variants in sync by hand.** `src/ui/entry_view/mod.rs:477-528, 594-612`. A new variant requires touching three else-if ladders. Extend the `EntryFieldRow` trait with `set_editable_mode / is_empty / drag_handle`.
- **`branch()` getter returns the unfiltered stored value via `as_deref`, but `set_branch` filters on `is_empty` after `trim`.** `src/app/controller.rs:96-103`. A caller storing `Some(" main ")` gets back `Some(" main ")`. Trim on store or trim on read; the half-trim is sharp.
- **`EntryView::show_error` on EntryView is named like an inline label but is actually an `adw::AlertDialog`.** `src/ui/entry_view/mod.rs:264-273`. Two functions (`EntryView::show_error` and `MainWindow::show_error_dialog`) with different names, both popping the same dialog, is more confusing than helpful. Rename or route through one helper.
- **`new_entry_dialog.rs:28` registers `GeneratePasswordView`'s GType every time the dialog is opened.** Idempotent so harmless, but registering once at app startup (next to the resource registration) makes the dialog code self-contained.
- **`PassNode::children` is always allocated even for entries.** `src/pass/model/pass_node.rs:18-19`. Empty Vecs don't allocate so the cost is just a pointer-tag, but `enum PassNodeKind { Group(Vec<PassNode>), Entry }` would let the type system enforce the invariant.

## Positive

- **Atomic-write protocol with per-byte rollback now has direct unit tests.** `src/pass/store/mod.rs:404-418, 676-734`. `write_atomically_replaces_destination_and_removes_temp` and `restore_previous_writes_back_or_removes` exercise the rollback primitive directly rather than only end-to-end. Previous-bytes capture before rename plus restore-and-restage on commit failure is exactly the rare "got it right" pattern.
- **`PgpError::Display` and `GitError::Display` redact upstream messages.** `src/helpers/pgp.rs:39-53`, `src/helpers/git.rs:58-84`. The comments explaining *why* gpgme stderr / libgit2 ref names must not reach a UI toast are exactly what future maintainers need; `backup_rejected_error_redacts_reason` (`git.rs:1025-1036`) pins the redaction so it can't drift.
- **`PgpError::decrypt` validates UTF-8 in place on `Zeroizing<Vec<u8>>` rather than via `String::from_utf8`.** `src/helpers/pgp.rs:76-88`. The failure path drops `plain` (which wipes its bytes) instead of moving them into a `FromUtf8Error`. The comment explains the choice.
- **Backup-ref accept-or-abort guard via `push_update_reference`.** `src/helpers/git.rs:373-396, 546-591, 938-1023`. Per-ref rejection is captured from the callback; rollback refuses the destructive reset if the backup wasn't accepted. `rollback_does_not_destroy_remote_when_backup_push_fails` is the right end-to-end shape.
- **`save_current_entry` cache-invariant phasing is clearly codified.** `src/app/controller.rs:350-425`. Three invariants stated, three phases inline-commented, `expect("session existed at phase start...")` instead of `ok_or` because the session was just proven and re-borrowing through `&mut self` cannot drop it. The kind of code that survives refactors.
- **Worker channels strip path-shaped data from `Failed` payloads, with comments at every relevant boundary.** `src/app/cache_warmup.rs:8-17`, `src/app/group_preview.rs:8-22`, `src/ui/window/autoload.rs:62-68`, `src/ui/window/group_content.rs:175-180`. "Pass-store paths are themselves the secret labels" reasoning is documented exactly where it would otherwise be tempting to undo.
- **`AppState` deliberately does not derive `Clone`.** `src/app/state/app_state.rs:10-14`. Cloning `AppState` would deep-clone the entry cache and multiply every plaintext `EntryField` allocation. Documenting *why* a missing impl is missing is the right move.
- **`EntrySession::Debug` and `EntryField::Debug` are hand-redacted under `cfg(not(test))` and verbose under `cfg(test)`.** `src/app/state/entry_session.rs:20-41`, `src/pass/model/entry_field.rs:21-46`. Assertable test output without leaking secret labels into release builds.
- **Snapshot-before-setter is consistent across every controller-touching window callback.** `src/ui/window/mod.rs:318-327, 373-379, 432-438, 522-529`. The `let (is_dirty, is_valid) = { let c = controller.borrow(); … };` pattern before any `view.set_*` is the right shape for a `Rc<RefCell<...>>` system that emits signals from setters; inline comments explain *why*.
- **Worker-thread cancellation is uniform between autoload and group-preview.** `src/ui/window/autoload.rs:38-50`, `src/ui/window/group_content.rs:150-159`. Both share an `Arc<AtomicBool>` between worker and polling tick; cells store the last-issued flag so external "stop" calls can signal cancel without racing with the timer's local clone.
- **`with_change` borrow-pattern is used in the `connect_bind` callback.** `src/ui/changes_view/mod.rs:168-185`. Saves a `GitChange::clone` per recycle. The accessor split between `change()` (clone) and `with_change(|c| ...)` (borrow) is the right shape.
- **`PasswordFieldRow::constructed` sets `InputHints::PRIVATE | NO_EMOJI | NO_SPELLCHECK`.** `src/ui/entry_view/fields/password_field_row/imp.rs:42-44`. The explicit `set_input_hints` is what stops ibus/fcitx/Orca/spellcheck from logging the password.
- **OTP timer lifecycle.** `src/ui/entry_view/fields/otp_field_row/mod.rs:90-118`, `imp.rs:71-80`. `connect_map`/`connect_unmap` bound the 1 Hz tick to on-screen time; `dispose` clears `timer_source`; `connect_map` defensively removes any pre-existing source. Three layers of "no orphan timer."
- **`generate_password`'s rejection-sampled `random_index` is unbiased.** `src/helpers/password.rs:74-86`. The `zone = u64::MAX - (u64::MAX % max_u64)` reject-and-retry is textbook unbiased sampling; the required-character placement plus Fisher-Yates shuffle makes the position uniformly random.
- **`set_password_store_dir_once` documents both soundness guarantees.** `src/pass/store/mod.rs:512-550`. The two-clause argument (`OnceLock` synchronization + main-thread-before-workers ordering) is exactly the right level of detail for an `env::set_var`. The fallback in `password_store_dir` to a relative path with a log warning instead of a panic is graceful in unusual session-manager environments.
- **`sanitize_user_id` strips bidi-override and control characters from key UIDs.** `src/helpers/pgp.rs:210-229`. The recipient picker can't be visually spoofed by a key with `U+202E` in its UID; `replaces_bidi_overrides_and_controls` pins it.

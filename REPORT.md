# Gnome-Vault — Code Review (round 3)

A pass-compatible password manager: GTK4/Adwaita + Rust, ~11k LOC, GPGME for crypto, git2 for sync. Two prior review rounds have closed the structural issues; this pass is grouped by severity and focuses on what's actually wrong NOW.

## Critical

## Important

**Atomic write does not fsync the parent directory after rename.** `src/pass/store/mod.rs:404-418`. `write_atomically` `sync_all`s the temp file then `fs::rename`s over the destination, but the rename's directory-entry change itself isn't fsynced — under power loss the on-disk view can revert to the prior content (best case) or expose the new file as zero-length (some filesystems / mount options). After a successful `fs::rename`, open `final_path.parent()` as a `File` and call `sync_all()` on it. One extra `fsync` per save and matches the standard POSIX "atomic write" shape.

**`mark_saved` overwrites the disk-truthful `node.name` with the user-typed candidate name.** `src/app/state/entry_session.rs:134-137`. After phase 1 of `save_current_entry`, `replace_node(renamed_node)` correctly puts the trimmed name from `pass::store::rename_entry` (which itself trims via `valid_entry_name`) into `session.node`. Phase 3 then calls `session.mark_saved()`, which does `self.node.name = self.name.clone()` — copying the *user-typed* untrimmed name back over the disk-truthful one. The session then claims "no name changes" against itself, but every subsequent diff against `node.name` is wrong: a follow-up rename computes `node.name == new_name` against the untrimmed value. Fix: in `mark_saved`, set `self.name = self.node.name.clone()` (treat `node` as authoritative after a save) instead of pushing the candidate `name` onto `node`.

**`revert_commit` leaves the repository in REVERT state when the index has conflicts.** `src/helpers/git.rs:319-360`. After `repo.revert(&commit, None)?` the repository's `.git/REVERT_HEAD` is set; the success path correctly calls `repo.cleanup_state()` and the "no changes" early-return does too — but the conflict early-return at lines 327-329 returns without cleanup. Subsequent operations see "you have a revert in progress" and refuse to commit until the user manually `git revert --abort`s. Add a `repo.cleanup_state()?` immediately before `return Err(GitError::Conflicts(...))`.

**`StoreError`'s data-bearing variants leak entry paths in `Debug` output.** `src/pass/store/store_error.rs:5-22`, `src/helpers/pgp.rs:13-30`. `MissingParent(PathBuf)`, `EmptyFile(PathBuf)`, `InvalidEntryName(String)`, `InvalidFolderPath(PathBuf)`, `DestinationExists(PathBuf)` all carry the secret-bearing path/name. `Display` correctly drops them and the comment warns against `{err:?}`, but the auto-derived `Debug` is the only thing standing between a future `log::warn!("{err:?}")` (or any `.unwrap()`/`.expect()` panic, which always uses `Debug`) and a journalctl entry containing the entry name. Apply the same hand-rolled `Debug` redaction `EntryField` already gets at `entry_field.rs:21-33`. Same exposure shape on `PgpError`'s `ContextError(String) / LoadingError(String) / DecryptError(String) / EncryptError(String) / NoKeys(String)` — gpgme stderr can echo recipient ids and absolute paths.

**Debug-level log prints `node.path.display()` on every cache hit/miss.** `src/app/controller.rs:245, 249`. Inside a password store, a path *is* the secret label — that's why `cache_warmup` and `group_preview` go to elaborate lengths to NOT thread paths through their `Failed` messages, and why every error `Display` is hand-redacted. A debug log that prints the raw path directly contradicts that posture and lands in journalctl on systemd setups when a user runs `RUST_LOG=debug` to file a bug report. Drop the path entirely and just say "entry cache hit" / "entry cache miss" — the call site already implies an entry — or log a hash/counter, never the raw path.

**`entry_matches_query` searches the cleartext value of `Password` and `OTP` field entries.** `src/app/controller.rs:471-476`. The session's primary `password` field is correctly excluded (the filter operates on `entry.fields`, not `entry.password`), but pass entries routinely store *additional* `EntryField::Password(...)` and `EntryField::OTP(...)` entries inside `fields` (a second password, a TOTP secret, recovery codes). Substring-matching the cleartext value of those leaks by-presence info via row-highlight on every keystroke, and on platforms where the query history is recovered (IM history, candidate windows on `gtk::SearchEntry` if it isn't all-`NO_SPELLCHECK`'d) the substring itself ends up in non-ephemeral state. Skip the value comparison when the field is `EntryField::Password` or `EntryField::OTP`; the *key* stays searchable so users still find "totp" by typing it.

**`controller.delete_folder` and `controller.delete_entry` don't validate the node kind.** `src/app/controller.rs:318-348`. Both unconditionally delegate to `pass::store::delete_*`. A UI mistake (wiring entry-context menu to the folder handler, or a refactor that swaps the two) would silently misroute the operation. `delete_folder` is partially protected because `remove_dir_all` on a file fails with `InvalidFolderPath`, but `delete_entry` would call `fs::remove_file` on a directory and surface a confusing "is a directory" error. Defending against UI boundary mistakes here costs two lines (`if !node.is_entry() { return Err(...) }`) and a clear error class.

**`evict_cached_entries_under` would silently nuke the whole cache on an empty prefix.** `src/app/state/app_state.rs:69-72` and `src/app/controller.rs:329`. `Path::starts_with("")` returns `true` for every path; calling `delete_folder` with a `PassNode { path: PathBuf::new(), ... }` (which the search-results pseudo-group already constructs at `src/ui/window/group_content.rs:48-53`) would defeat the round-2 scoped-eviction fix. Today the store layer happens to reject empty paths via `is_dir()` checks, but the cache should not depend on that coincidence. Return early in `evict_cached_entries_under` when `prefix.as_os_str().is_empty()`, or `debug_assert!` against it.

**Strong-self captures form a `MainWindow` ↔ template-child reference cycle.** `src/ui/window/mod.rs:87-509` (every `let window = self.clone();` in `setup_callbacks`), `src/ui/window/autoload.rs:42-43`, `src/ui/window/group_content.rs:154-155`. Each closure connected to a template child holds a strong `MainWindow` reference; the template child is itself owned by the window, so the cycle is `MainWindow → template_child → handler → MainWindow`. Today benign — the app holds a single `MainWindow` and disposes it at exit — but the `glib::clone!(#[weak(rename_to = window)] self, ...)` shape is already used in `preferences.rs` and `new_entry_dialog.rs`. Convert `setup_callbacks` and the two timers to weak captures so the window is safe to destroy independently of the app shell, and so a closed-but-not-disposed window with a still-running autoload tick can actually finish.

**Toggling autoload off-then-on within ~100 ms silently no-ops.** `src/ui/window/autoload.rs:26-31`, `src/ui/window/preferences.rs:76-98`. `start_autoload_cache` early-returns when `autoload_running` is true; `stop_autoload_cache` sets the cancel flag but leaves `autoload_running` set until the next 100-ms tick observes the flag and clears it. A misclick on the switch — off then on inside that window — hits the early-return and autoload never restarts until the user nudges it again. Either drain `autoload_running` synchronously inside `stop_autoload_cache`, or have `start_autoload_cache` clear an in-flight worker on its own.

**Entry deletion has no confirmation dialog.** `src/ui/window/mod.rs:401-419, 540-567`. Both delete paths (footer button + vault-view right-click) call `controller.borrow_mut().delete_*` directly. `confirm_delete_folder`, `confirm_revert_change`, and `confirm_rollback_change` all gate on an `adw::AlertDialog` with a `Destructive`-styled response. Deleting a single entry is just as destructive (commit lands, autopush fires, decrypted cache evicts). Wrap both call sites in the same confirm shape.

**`PasswordFieldRow::set_entry_field` accepts any `EntryField` variant and writes its `display_value()` into the password entry.** `src/ui/entry_view/fields/password_field_row/mod.rs:72-77`. Other field rows guard with `if let EntryField::Variant(...) = field`; this one calls `set_text(&field.display_value())` unconditionally. For an `EntryField::Array(values)`, `display_value()` returns `values.join("\n")`, so array elements would land verbatim in the cleartext password row — visible after the eye-toggle, copied by the copy button, and saved back as the new primary password. Only safe today because the single call site routes OTP elsewhere and trusts `EntryData::password` to be `EntryField::Password`. Match `EntryField::Password(s) => self.set_text(s)`, `log::warn!` on the rest.

**`MultilineFieldRow` rebuilds the markdown view on every keystroke.** `src/ui/entry_view/fields/multiline_field_row/mod.rs:39-48, 133-146`. `buffer.connect_changed` calls `sync_value_view`, which calls `clear_box(value_view_box)` and constructs a fresh `MarkdownTextView` (re-parses the markdown into a fresh TextBuffer with formatting tags) per character. The view-mode widget is hidden during typing, so the work is invisible. Gate `sync_value_view` on `!self.imp().value_text_view.is_editable()`, or hoist the markdown view into a `OnceCell<MarkdownTextView>` and only swap widgets when the markdown setting toggles.

**`ArrayFieldRow::set_entry_field(field)` discards the parent `EntryView`, breaking the dirty-mark wiring on subsequent edits.** `src/ui/entry_view/fields/array_field_row/mod.rs:224-228`. The setter calls `self.set_values(values, None)` → `append_value_entry(value, None)`, which *skips* the `entry.connect_changed` wiring (line 148 guards on `Some`). The trait contract says `set_entry_field` should round-trip; today nobody calls it (the EntryView rebuilds the row from scratch on `set_entry_data`), but the moment they do, edits inside the array no longer mark the entry view dirty. Store the `glib::WeakRef<EntryView>` set in `new_empty` on the `imp` struct, and have `append_value_entry` upgrade-and-wire from there.

## Minor

- **Setter holds an `AppController` immutable borrow across a `ListModel::items_changed` notification.** `src/ui/window/group_content.rs:131-145`. The cache-hit loop holds `controller.borrow()` for its entire duration and synchronously calls `update_entry_subtitle`, which fires `model.items_changed`. No current listener re-enters the controller, but the snapshot pattern used elsewhere is the safe shape: collect `(index, subtitle)` while the borrow is live, drop the borrow, then call setters.
- **`unsafe { row.set_data / data }` in `ChangesView` depends on a key string.** `src/ui/changes_view/mod.rs:128-130, 190-217`. `data::<T>()` casts blindly to `T`; if anyone collides on `"changes-row-current"` with a different type, the deref is UB. Either wrap the type in a newtype that's unique to this call site, or consider an alternative storage shape that doesn't need `unsafe`.
- **`setup_vault` clears cache before reload still reports the previous tree.** `src/app/controller.rs:109-118`. The reorder lands first, but if the *new* `load_password_store` returns `Ok(empty_vec)` on a freshly-init'd vault with only `.gpg-id`, the user sees an empty vault while the cache they had has been cleared. Cosmetic.
- **`select_node_by_path`'s return value is ignored at the only call site.** `src/ui/window/mod.rs:355`. If the parent node was filtered out of the current tree by an active search, the previous selection silently persists. A debug-level log on the `false` branch would make this debuggable.
- **Default fallbacks in `setting_boolean` disagree with the gschema defaults.** `src/ui/window/mod.rs:885-887` (`show-group-view` falls back to `false`; gschema default is `true`), `src/ui/window/preferences.rs:43-44` (`interpret-multiline-as-markdown` falls back to `false`; gschema default is `true`). Mirror the schema, not the opposite.
- **`set_edit_unlock_state(true, editing, false)` from the lock button hard-codes `is_dirty = false`.** `src/ui/window/mod.rs:453-457`. Correct only because the lock button is gated insensitive when dirty; the third argument silently lies if the gating ever changes. Read the actual `is_dirty` from a snapshot.
- **`apply_branch_setting` and `branch_row.connect_apply` both call `refresh_changes_badge`, then the apply handler calls `reload_changes_view` which calls `refresh_changes_badge` again.** `src/ui/window/setup.rs:63-80`, `src/ui/window/preferences.rs:198-220`. Pick one owner of the refresh.
- **`revert_change` and `rollback_change` clear the entry cache but don't restart autoload.** `src/ui/window/mod.rs:680-690, 749-758`. After either operation the user with "Load entries at startup" enabled finishes with a cold cache until next launch. Call `start_autoload_if_enabled` after the post-revert UI reset.
- **`AppError::Save(StoreError)` swallows `PushFailed` semantics.** `src/app/app_error.rs:1-46`, `src/pass/store/store_error.rs:14-22`. `StoreError::PushFailed` is distinguished specifically so the UI can give "saved locally, push failed" — but everything goes through `From<StoreError> for AppError` and collapses. The `Display` string preserves the distinction; no caller can branch on it without re-introspecting `StoreError`. Lift `PushFailed` to `AppError::PushFailed(String)` directly, or expose `AppError::store_error(&self) -> Option<&StoreError>`.
- **`cache_warmup` and `group_preview` message types disagree on shape.** `src/app/cache_warmup.rs:8-17` (`Failed(usize, String)`) vs `src/app/group_preview.rs:8-23` (`Failed { index, error }`). Both are the same protocol with same threading model. Unify on the named-fields shape, or extract a single `app::entry_loader` parameterized over per-row context.
- **`PgpError::Utf8Error` carries a stale string literal.** `src/helpers/pgp.rs:80-84`. Every call site stuffs the same hardcoded text. Simplify to a unit variant.
- **`percent_decode` mishandles a `%XX` escape at the very end of a query value.** `src/helpers/otp.rs:180`. The guard is `b'%' if index + 2 < bytes.len()`, which excludes the case where `%XX` IS the last three bytes (then `index + 2 == bytes.len() - 1`, the slice `value[index + 1..index + 3]` would still be in bounds). A trailing `%2F` falls into the byte branch and `%`, `2`, `F` survive into base32 decoding. Change the guard to `index + 3 <= bytes.len()`. Add a regression test for `secret=ABCD%2F` at the URL tail.
- **`setup_vault` doesn't validate the recipient against `pgp::available_recipients()` output structure.** `src/pass/store/mod.rs:117-123`. The check `candidate.id == recipient` works against raw fingerprint/key-id strings, but `available_recipients` populates `id` via `key.fingerprint().or_else(key.id())` — fingerprint vs short-id can mismatch on the same key. Edge case for users who configure GSettings by hand.
- **`save_current_entry`'s `let _ = old_path` is dead code.** `src/app/controller.rs:422`. Either use the binding (e.g. `debug_assert!(self.state.cached_entry(&path).is_none())` on the old path before installing the new) or remove it entirely. The "// already removed above; bind to mark intent" comment misleads.
- **`rebuild_vault_tree` calls `update_selection_layout(false)` on every search keystroke.** `src/ui/window/mod.rs:784-798`. Layout doesn't change between keystrokes; only the selection model does.
- **`EntryView::resize_title_entry` runs per keystroke and also updates the hidden `title_label`.** `src/ui/entry_view/mod.rs:433-444, 123-133`. The label is only visible when the entry is hidden. Move the label update into `set_editable_mode(false)` so it refreshes when leaving edit mode, not on every keystroke.
- **Magic numbers `Duration::from_millis(100)`, `Duration::from_millis(50)`, `for _ in 0..32`, `for _ in 0..16` in autoload + group_content.** `src/ui/window/autoload.rs:43, 54`, `src/ui/window/group_content.rs:151, 156`. Pull these next to the existing `CHANGES_PAGE_SIZE` etc. consts so the polling cadence is one grep away.
- **`is_otp_url` uses `get(..10)` rather than `is_char_boundary`-aware slicing.** `src/helpers/otp.rs:33-38`. `get(..10).is_some_and(|p| p.eq_ignore_ascii_case("otpauth://"))` works but is awkward. Cosmetic.
- **`EntryView::set_field_row_editable`, `read_field_row`, and `field_row_drag_handle` keep four field-row variants in sync by hand.** `src/ui/entry_view/mod.rs:477-528, 594-612`. A new variant requires touching three else-if ladders. Extend the `EntryFieldRow` trait with `set_editable_mode / is_empty / drag_handle`.
- **`branch()` getter returns the unfiltered stored value via `as_deref`, but `set_branch` filters on `is_empty` after `trim`.** `src/app/controller.rs:96-103`. A caller storing `Some(" main ")` gets back `Some(" main ")`. Trim on store or trim on read; the half-trim is sharp.
- **`EntryView::show_error` on EntryView is named like an inline label but is actually an `adw::AlertDialog`.** `src/ui/entry_view/mod.rs:264-273`. Two functions (`EntryView::show_error` and `MainWindow::show_error_dialog`) with different names, both popping the same dialog, is more confusing than helpful. Rename or route through one helper.
- **`new_entry_dialog.rs:28` registers `GeneratePasswordView`'s GType every time the dialog is opened.** Idempotent so harmless, but registering once at app startup (next to the resource registration) makes the dialog code self-contained.
- **`PassNode::children` is always allocated even for entries.** `src/pass/model/pass_node.rs:18-19`. Empty Vecs don't allocate so the cost is just a pointer-tag, but `enum PassNodeKind { Group(Vec<PassNode>), Entry }` would let the type system enforce the invariant.

## Positive

- **Atomic-write protocol with per-byte rollback now has direct unit tests.** `src/pass/store/mod.rs:404-418, 676-734`. `write_atomically_replaces_destination_and_removes_temp` and `restore_previous_writes_back_or_removes` exercise the rollback primitive directly rather than only end-to-end. Previous-bytes capture before rename plus restore-and-restage on commit failure is exactly the rare "got it right" pattern.
- **`PgpError::Display` and `GitError::Display` redact upstream messages.** `src/helpers/pgp.rs:39-53`, `src/helpers/git.rs:58-84`. The comments explaining *why* gpgme stderr / libgit2 ref names must not reach a UI toast are exactly what future maintainers need; `backup_rejected_error_redacts_reason` (`git.rs:1025-1036`) pins the redaction so it can't drift.
- **`PgpError::decrypt` validates UTF-8 in place on `Zeroizing<Vec<u8>>` rather than via `String::from_utf8`.** `src/helpers/pgp.rs:76-88`. The failure path drops `plain` (which wipes its bytes) instead of moving them into a `FromUtf8Error`. The comment explains the choice.
- **Backup-ref accept-or-abort guard via `push_update_reference`.** `src/helpers/git.rs:373-396, 546-591, 938-1023`. Per-ref rejection is captured from the callback; rollback refuses the destructive reset if the backup wasn't accepted. `rollback_does_not_destroy_remote_when_backup_push_fails` is the right end-to-end shape.
- **`save_current_entry` cache-invariant phasing is clearly codified.** `src/app/controller.rs:350-425`. Three invariants stated, three phases inline-commented, `expect("session existed at phase start...")` instead of `ok_or` because the session was just proven and re-borrowing through `&mut self` cannot drop it. The kind of code that survives refactors.
- **Worker channels strip path-shaped data from `Failed` payloads, with comments at every relevant boundary.** `src/app/cache_warmup.rs:8-17`, `src/app/group_preview.rs:8-22`, `src/ui/window/autoload.rs:62-68`, `src/ui/window/group_content.rs:175-180`. "Pass-store paths are themselves the secret labels" reasoning is documented exactly where it would otherwise be tempting to undo.
- **`AppState` deliberately does not derive `Clone`.** `src/app/state/app_state.rs:10-14`. Cloning `AppState` would deep-clone the entry cache and multiply every plaintext `EntryField` allocation. Documenting *why* a missing impl is missing is the right move.
- **`EntrySession::Debug` and `EntryField::Debug` are hand-redacted under `cfg(not(test))` and verbose under `cfg(test)`.** `src/app/state/entry_session.rs:20-41`, `src/pass/model/entry_field.rs:21-46`. Assertable test output without leaking secret labels into release builds.
- **Snapshot-before-setter is consistent across every controller-touching window callback.** `src/ui/window/mod.rs:318-327, 373-379, 432-438, 522-529`. The `let (is_dirty, is_valid) = { let c = controller.borrow(); … };` pattern before any `view.set_*` is the right shape for a `Rc<RefCell<...>>` system that emits signals from setters; inline comments explain *why*.
- **Worker-thread cancellation is uniform between autoload and group-preview.** `src/ui/window/autoload.rs:38-50`, `src/ui/window/group_content.rs:150-159`. Both share an `Arc<AtomicBool>` between worker and polling tick; cells store the last-issued flag so external "stop" calls can signal cancel without racing with the timer's local clone.
- **`with_change` borrow-pattern is used in the `connect_bind` callback.** `src/ui/changes_view/mod.rs:168-185`. Saves a `GitChange::clone` per recycle. The accessor split between `change()` (clone) and `with_change(|c| ...)` (borrow) is the right shape.
- **`PasswordFieldRow::constructed` sets `InputHints::PRIVATE | NO_EMOJI | NO_SPELLCHECK`.** `src/ui/entry_view/fields/password_field_row/imp.rs:42-44`. The explicit `set_input_hints` is what stops ibus/fcitx/Orca/spellcheck from logging the password.
- **OTP timer lifecycle.** `src/ui/entry_view/fields/otp_field_row/mod.rs:90-118`, `imp.rs:71-80`. `connect_map`/`connect_unmap` bound the 1 Hz tick to on-screen time; `dispose` clears `timer_source`; `connect_map` defensively removes any pre-existing source. Three layers of "no orphan timer."
- **`generate_password`'s rejection-sampled `random_index` is unbiased.** `src/helpers/password.rs:74-86`. The `zone = u64::MAX - (u64::MAX % max_u64)` reject-and-retry is textbook unbiased sampling; the required-character placement plus Fisher-Yates shuffle makes the position uniformly random.
- **`set_password_store_dir_once` documents both soundness guarantees.** `src/pass/store/mod.rs:512-550`. The two-clause argument (`OnceLock` synchronization + main-thread-before-workers ordering) is exactly the right level of detail for an `env::set_var`. The fallback in `password_store_dir` to a relative path with a log warning instead of a panic is graceful in unusual session-manager environments.
- **`sanitize_user_id` strips bidi-override and control characters from key UIDs.** `src/helpers/pgp.rs:210-229`. The recipient picker can't be visually spoofed by a key with `U+202E` in its UID; `replaces_bidi_overrides_and_controls` pins it.

## Suggested fix order

1. The four **Critical** items — they're cheap to fix and silently leak.
2. `revert_commit` cleanup-on-conflict + encrypt-path key validation + atomic-write parent fsync — error-recovery posture.
3. `mark_saved` name drift + `evict_cached_entries_under` empty-prefix guard — state machine integrity.
4. Strong-self captures in window setup_callbacks + autoload toggle race + entry-delete confirm — UX hardening.
5. `Debug` redaction on `StoreError` / `PgpError` data variants + cache hit/miss log — security posture.
6. `entry_matches_query` skipping Password/OTP values — search-side leak.
7. `PasswordFieldRow` variant guard + `MultilineFieldRow` keystroke rebuild + `ArrayFieldRow` setter wiring — UI correctness.
8. The Minor list in any order; most are small.
